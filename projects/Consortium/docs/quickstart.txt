¶

MockLLMProvider
. Цель — продемонстрировать архитектурный паттерн Brain / Hands / Session и event log в работе.

Разбор архитектуры
¶
Метод
handle_user_message(session_id, content)
выполняет следующую последовательность:
sequenceDiagram
    actor User
    participant H as Harness (Brain)
    participant L as MockLLMProvider
    participant S as SQLiteSessionStore (Session)

    User->>H: handle_user_message("Привет!")
    H->>S: emit message.user
    H->>S: emit model.called
    H->>L: call(messages, tools=[])
    L-->>H: ModelResponse
    H->>S: emit model.responded
    H->>S: emit message.assistant
    H-->>User: ModelResponse
SessionStore.
Append-only журнал (
ADR-0004
). Каждый turn производит не менее трёх событий. Состояние сессии = свёртка над журналом. Реализация для production —
PostgresSessionStore
(
ADR-0032
) с тем же контрактом.
Agent.
Носитель идентичности (
agent_id
— UUID). К нему привязаны сессии и memory (
ADR-0011
). Сессии — представления над identity-bound state.
MockLLMProvider.
Реализация
LLMProvider
Protocol. Возвращает заготовленные
ModelResponse
. В production заменяется на
OpenRouterProvider
(default — ADR-0007) или
AnthropicProvider
(text-only — ADR-0084).
Harness.
Stateless dispatcher. Метод
wake(session_id)
восстанавливает контекст из event log при перезапуске.
Что дальше
¶
Расширение функциональности.
Учебник
содержит 10 рецептов: реальная модель через OpenRouter, регистрация tools, three-tier memory, plan-only policy, replay сессии, custom Tool, multi-agent через delegate, multimodal, CaMeL.
Архитектурное обоснование.
Философия → Brain / Hands / Session
— детальный разбор главного инварианта.
Философия → Labeled untrusted
— канонический ответ на prompt injection.
Production deployment.
Используемая в этом примере конфигурация (
SQLiteSessionStore
+
MockLLMProvider
+
InProcessBackend
) рассчитана на разработку и unit-тесты. Production-конфигурация — Postgres, vault, mitmproxy sidecar, GVisor sandbox, K8s Helm chart — описана в разделе
Production
. Запуск
