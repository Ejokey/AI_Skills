Memory — three-tier
¶
Identity-bound memory: привязана к
agent_id
, не к
session_id
. Сессии — представления над identity-bound state.

Core memory blocks
¶
Заметки длиной не более 8K символов на блок и не более 16K суммарно на агента. Инжектятся в system prompt каждого turn'а через
reduce_events_to_messages
. API — tool
memory_block
с операциями
read / write / list / delete
. Имена блоков проходят snake_case валидацию (regex
^[a-z][a-z0-9_]*$
).
Пример содержимого:
[persona]
Имя — Иван. Работает в финтех. Предпочитает короткие ответы.
[preferences]
Язык — русский. Часовой пояс — Europe/Moscow.
Archival entries
¶
Долгосрочное хранилище фактов с категориями (около 10 типов в стиле Memanto:
preference
,
health
,
profile
и других). Hybrid retrieval:
BM25 × cosine_similarity × recency_decay × √importance
. API —
memory_archive
для записи и
memory_search
для чтения. Identity isolation проверяется контракт-тестами: agent A не видит archival entries agent B. Expired entries (по
expires_at
) фильтруются в search.
Recall — cross-session message history
¶
FTS5 индекс над message bodies всех сессий того же
agent_id
(ADR-0093). API — tool
memory_recall
(Phase A) и
Harness(recall_store=...)
auto-indexer (Phase B).

Sleep-time consolidation (ADR-0058 + 0074)
¶
Batch-сервис, периодически (cron в production driver) выполняющий:
Чтение recent archival entries в TTL window.
LLM-driven summarization: группировка related entries в semantic clusters.
Запись summary entries с повышенной importance, деактивация оригиналов.

Identity invariants
¶
Core blocks isolated по
agent_id
(контракт-тест).
Archival entries isolated по
agent_id
.
Recall —
agent_id
-scoped, не session-scoped.
Sub-agents через
delegate
могут получить
ParentScopedMemoryManager
(read-only view на parent's memory и write в собственную), ADR-0052.
