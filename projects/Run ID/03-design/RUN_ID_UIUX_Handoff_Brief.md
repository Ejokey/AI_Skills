# RUN.ID — бриф для UI/UX-дизайнера (макеты экранов MVP)

Составлено бизнес-аналитиком на основе `RUN_ID_Business_Analysis_Package.docx` (BRD, Use Cases, User Stories, FRS) и `RUN_ID_Diagrams_and_Visualizations.docx`. Источник продуктовой логики — `RUN_ID_MVP_analysis.docx`.

**Задача дизайнера:** макеты всех P0-экранов должны быть готовы в первые 1–2 недели разработки (5–6-недельный спринт), иначе они блокируют фронтенд. Стек фронтенда — React + TypeScript, адаптивный веб/PWA (единственный клиент, десктоп + мобильный браузер, без нативных сторов).

---

## 1. Продукт в двух предложениях

RUN.ID — российский аналог Strava: GPS-трекер тренировок (загрузка .fit/.gpx с часов, без записи с телефона в MVP) с сегментами/лидербордами, базовой социальной лентой и платным цифровым членством, дающим доступ к каталогу привилегий от партнёров. Монетизируемая ценность продукта — не техническая часть, а партнёрская экосистема членства, поэтому её экраны имеют тот же приоритет P0, что и трекинг.

## 2. Сквозные ограничения дизайна (держать в голове на каждом экране)

1. **Только бег, только загрузка файла.** Нет записи тренировки в реальном времени в MVP — не проектировать экран «Старт/Стоп тренировки».
2. **Gating по членству.** Каталог привилегий виден всем, но промокод/условие скрыто без активного членства — нужен явный визуальный паттерн "заблокировано, оформи членство" (переиспользуется на 2+ экранах).
3. **Privacy zones.** Публичная карта чужой тренировки может иметь обрезанный участок маршрута — предусмотреть визуальное обозначение "скрытый участок", не пустую дыру без объяснения.
4. **152-ФЗ.** Нужна ссылка на политику конфиденциальности (футер/онбординг) и экран/диалог удаления аккаунта.
5. **Асинхронная обработка.** Загрузка тренировки — не мгновенная: нужен статус "в обработке" (не блокирующий, пользователь может уйти на другой экран) и статусы ошибки/дубликата.
6. **Одна колонка адаптива.** Один и тот же макет должен читаться и на desktop, и в мобильном браузере — не проектировать отдельно "мобильное приложение".

## 4. Экраны по порядку пользовательского пути

### 4.1 Регистрация / Вход — P0
- **Цель пользователя:** быстро попасть в приложение.
- **Элементы:** email/телефон + пароль, переключение регистрация↔вход, ссылка на политику конфиденциальности.
- **Состояния:** пустое, ошибка валидации формата, "email уже используется" → предложить войти/восстановить пароль.
- **Данные:** нет предзаполнения.

### 4.2 Профиль (свой) — P0
- **Цель:** ощущение прогресса + управление аккаунтом.
- **Элементы:** аватар, имя, суммарные км/часы/число тренировок, список последних тренировок, кнопка "Загрузить тренировку", ссылка на настройки, статус членства (badge).
- **Состояния:** новый пользователь без тренировок → нулевые значения без ошибки, не пустой экран-заглушка "загрузите первую тренировку".
- **Настройки (тот же раздел или подэкран):** аватар, единицы измерения (км/мили), видимость профиля (публичный/только подписчики), удаление аккаунта.

### 4.3 Загрузка тренировки + статус — P0
- **Цель:** отдать файл, не ждать зря.
- **Элементы:** зона загрузки файла (.fit/.gpx, до 20 МБ), после отправки — неблокирующий статус "в обработке" (можно уйти с экрана).
- **Состояния:** processing → processed (редирект на детали тренировки) / failed (нет GPS-данных) / duplicate (тренировка уже загружена) / неподдерживаемый формат при выборе файла.

### 4.4 Детали тренировки — P0
- **Цель:** "вау-эффект" сразу после тренировки, разбор данных.
- **Элементы:** карта маршрута с окраской по темпу/пульсу (переключатель темп↔пульс), графики темпа/пульса/высоты, таблица сплитов по км, сводка (ср./макс. темп, ср./макс. пульс, набор высоты, moving vs elapsed time, калории), список найденных сегментов на этом треке, кнопка "Создать сегмент", лайк + счётчик.
- **Состояния:** нет данных пульса → график пульса скрыт, остальное работает; приватная зона обрезает публичный показ маршрута для чужих зрителей (сам автор видит полный трек).

### 4.5 Создание сегмента — P0
- **Цель:** выделить участок и превратить в соревновательный маршрут.
- **Элементы:** карта тренировки с возможностью выбрать начальную/конечную точку, поле "название сегмента".
- **Состояния:** участок короче минимальной длины (~500 м) → предупреждение; сегмент с идентичной геометрией уже существует → предложить использовать существующий вместо создания нового.

### 4.6 Экран сегмента (лидерборд) — P0
- **Элементы:** название/карта сегмента, дистанция, список прохождений по времени (лидерборд), выделена позиция текущего пользователя, его личный рекорд.
- **Состояния:** пользователь ещё не проходил сегмент → общий лидерборд без выделения + призыв "пробеги этот сегмент".

### 4.7 Лента активностей — P0
- **Элементы:** хронологический список тренировок подписок (карточка: автор, дата, дистанция/время/темп, мини-карта, лайк+счётчик), переход в детали тренировки или в профиль автора.
- **Состояния:** пустая лента (нет подписок) → призыв найти и подписаться на бегунов (ведёт к поиску).

### 4.8 Чужой профиль + поиск — P0
- **Элементы:** поиск по имени (от 2 символов, пустой результат — не ошибка), карточка чужого профиля со статистикой, кнопка "Подписаться"/"Отписаться" (без подтверждения второй стороной).

### 4.9 Моё членство + оплата — P0
- **Цель:** ключевое отличие от Strava, основа монетизации — не второстепенный экран.
- **Элементы:** статус (нет членства / ожидает оплаты / активно / истекло), кнопка "Оформить членство" → переход на оплату (ЮKassa/Robokassa), после оплаты — автоматическая активация.
- **Состояния:** оплата отклонена/отменена → понятная ошибка + повтор; пользователь закрыл страницу оплаты не завершив → статус "ожидает оплаты" до тайм-аута.

### 4.10 Каталог привилегий партнёров — P0
- **Элементы:** список 2–3 партнёров (лого, описание привилегии), при клике — условия + промокод.
- **Состояния — важно для дизайна:** без активного членства каталог виден, но промокод скрыт (ознакомительный режим) с явным CTA "оформи членство, чтобы получить код". Это тот самый gating-паттерн из раздела 2.

### 4.11 RunFriendly-места — P1
- Карта/список статических точек (название, координаты, описание), контент вносится администратором вручную — дизайну не нужен экран создания/редактирования (это админка, вне пользовательского MVP).

### 4.12 Календарь событий — P1
- Список предстоящих событий (название, дата, организатор), сортировка по дате, прошедшие не показываются.

### 4.13 Настройки приватности (privacy zone) — P1
- **Элементы:** указать точку на карте (адрес/геометка) + радиус, список уже заданных зон.
- **Состояния:** слишком большой радиус → предупреждение "скроет значительную часть маршрута".

### 4.14 Удаление аккаунта — P1
- Диалог подтверждения (повторный пароль/email-подтверждение) + предупреждение о необратимости (право на забвение, 152-ФЗ).

## 5. Что НЕ проектировать в этом заходе (вне MVP)

Запись тренировки на телефоне (старт/стоп/трек в реальном времени), нативное мобильное приложение, мультиспорт (вело/хайкинг), продвинутая аналитика (TSS/TRIMP/VO2max), клубы/групповые челленджи/личные сообщения, физическая карта/браслет членства, лидерборд среди подписок, promo/trial/рекуррентные платежи, тепловая карта B2G, импорт из Toplist.run/S10.run/Strava. Полный список — BRD раздел 5.2 «Out-of-Scope».

## 6. Открытые вопросы к продакт-оунеру перед финальной версткой каталога и оплаты

1. Какие именно 2–3 партнёра будут в каталоге на старте — нужны их лого/бренд-гайды для верстки карточек.
2. ЮKassa или Robokassa — от этого зависит, чей платёжный виджет/брендинг встраивать в экран оплаты.
3. Устраивает ли формат "простого разового платежа" визуально (без выбора тарифа/подписки) на MVP.

## 8. Цветовая палитра

### 8.1 Извлечено из презентации (`run id общая.pdf`)

Цвета получены программным разбором векторных заливок PDF (реальные цвета фигур/акцентов в слайдах, а не цвета случайных фотографий). Отсортированы по частоте использования.

| Цвет | HEX | Похоже на роль в презентации |
|---|---|---|
| 🟧 | `#FF5400` | Главный акцент — самый частый цветной (не серый/чёрно-белый) цвет в деке, энергичный оранжевый |
| 🟦 | `#009DFF` | Второй акцент — яркий голубой |
| 🟦 | `#464F8B` | Тёмно-индиговый — поддерживающий цвет |
| 🟪 | `#6E79AC` | Приглушённый сине-фиолетовый |
| 🟪 | `#B547E2` | Фиолетовый — редкий акцент |
| ⬛ | `#1C1C1F` / `#2B2B31` | Почти чёрные — тёмные поверхности/фон |
| ⬜ | `#4A4A4A` / `#7E7C83` / `#9A9A9A` | Серые — текст на светлом фоне |
| ⬜ | `#E0E0E0` / `#D9D9D9` | Светло-серые — разделители/фон |
| 🔷 | `#F0F7FD` / `#DCE3F8` / `#C9D7FF` | Светло-голубые — мягкий фон подложек/бейджей |

**Вывод:** презентация построена на паре оранжевый + голубой с фиолетовым как редким третьим акцентом на тёмной/нейтральной серой подложке — узнаваемая, энергичная связка, уместная для бегового бренда (перекликается со Strava по духу «оранжевый = энергия», но за счёт голубого и тёмной темы не копирует её один в один).

### 8.2 Предлагаемый вариант для UI приложения (адаптация под экраны, не под слайды)

Палитра презентации хороша как айдентика, но для интерфейса нужны чёткие семантические роли и цвета состояний, которых в презентации нет (успех/ошибка/ожидание). Предлагаю:

| Роль | Цвет | HEX | Где использовать |
|---|---|---|---|
| Primary / CTA | 🟧 Оранжевый | `#FF5400` | Главная кнопка, активная вкладка, акцент «Оформить членство» |
| Secondary / Info | 🟦 Голубой | `#009DFF` | Ссылки, окраска темпа на карте, информационные иконки |
| Accent / Premium | 🟪 Фиолетовый | `#B547E2` | Только бейджи привилегий/премиум-меток — редко, чтобы не спорить с оранжевым CTA |
| Dark surface (опц. тёмная тема) | ⬛ | `#1C1C1F` / `#2B2B31` | Фон / карточки в тёмной теме, оверлей на карте |
| Текст основной | ⬛ | `#222222` | Основной текст на светлом фоне |
| Текст вторичный | ⬜ | `#4A4A4A` / `#9A9A9A` | Подписи, плейсхолдеры, disabled |
| Разделители/фон | ⬜ | `#E0E0E0` | Границы, светлый фон карточек |
| Мягкая подложка | 🔷 | `#F0F7FD` | Фон бейджей/уведомлений на светлой теме |
| Success (нов.) | 🟩 | `#34C759` | Тренировка обработана, членство активно |
| Warning (нов.) | 🟨 | `#FFB020` | Статус «в обработке», «ожидает оплаты» |
| Error (нов.) | 🟥 | `#FF3B30` | Ошибка формата, дубликат, отклонённый платёж |

Логика: оранжевый и голубой из презентации переиспользуются как есть — они уже «бренд». Фиолетовый оставлен, но сознательно ограничен только премиум/партнёрскими бейджами, иначе три ярких цвета одновременно перегружают интерфейс. Серая и голубая светлая шкала presentaции подходит как есть под текст/фон. Success/Warning/Error добавлены — в презентации их не было, но без них не показать статусы «в обработке», «дубликат», «оплата не прошла» (см. раздел 2, пункт 5).
