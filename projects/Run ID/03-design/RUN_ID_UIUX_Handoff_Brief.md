## 1. Продукт в двух предложениях

RUN.ID — российский аналог Strava: GPS-трекер тренировок (загрузка .fit/.gpx с часов, без записи с телефона в MVP) с сегментами/лидербордами, базовой социальной лентой и платным цифровым членством, дающим доступ к каталогу привилегий от партнёров. Монетизируемая ценность продукта — не техническая часть, а партнёрская экосистема членства, поэтому её экраны имеют тот же приоритет P0, что и трекинг.

## 2. Сквозные ограничения дизайна на MVP (держать в голове на каждом экране)

1. Только бег, только загрузка файла. Нет записи тренировки в реальном времени в MVP — не проектировать экран «Старт/Стоп тренировки».

2. Gating по членству. Каталог привилегий виден всем, но промокод/условие скрыто без активного членства — нужен явный визуальный паттерн «заблокировано, оформи членство» (переиспользуется на 2+ экранах).

3. Privacy zones. Публичная карта чужой тренировки может иметь обрезанный участок маршрута — предусмотреть визуальное обозначение «скрытый участок», не пустую дыру без объяснения.

4. 152-ФЗ. Нужна ссылка на политику конфиденциальности (футер/онбординг) и экран/диалог удаления аккаунта.

5. Асинхронная обработка. Загрузка тренировки — не мгновенная: нужен статус «в обработке» (не блокирующий, пользователь может уйти на другой экран) и статусы ошибки/дубликата.

6. Одна колонка адаптива. Один и тот же макет должен читаться и на desktop, и в мобильном браузере — не проектировать отдельно «мобильное приложение».

Статус на 19.08.2026 — без изменений с 16.08.2026: пункт 3 (privacy zones) реализован иначе, чем описано (см. §4.13 ниже — механика теперь ещё раз изменилась). Пункт 4 (152-ФЗ) — футер и ссылки свёрстаны, тексты документов не опубликованы, экран удаления аккаунта вне текущего скоупа бэкенда.

## 4. Экраны по порядку пользовательского пути

## 6. Открытые вопросы к продакт-оунеру — актуализировано 19.08.2026

1. Какие именно 2–3 партнёра будут в каталоге на старте. Частично снято: на сайте уже есть реальные карточки Спортмастера — уточнить, добавляются ли ещё партнёры.

2. ЮKassa или Robokassa — закрыто: ЮKassa, решение принято 16.08.2026.

3. Формат «разового платежа» — закрыто 19.08.2026: реализованный экран оплаты прямо подписан «Разовый платёж, без автопродления» на обоих тарифах. Расхождение со статусом членства «активна до 23 апреля 2027», замеченное во второй волне, скорее всего было тестовыми данными — можно официально зафиксировать модель как решённую.

4. Минимальная длина сегмента и правило дедупликации при создании — не снято, по-прежнему не описано ни в одном источнике.

5. Нужен ли экран/раздел «Календарь событий» в MVP — не снято. Появление пустого раздела Events в админке не отвечает на вопрос приоритета, только резервирует место в структуре.

6. Дублирование «Политика обработки персональных данных» / «Политика конфиденциальности» в футере — не снято.

7. Приоритет мультиспорта («Хайк» в фильтрах при заявленном фокусе на бег) — не снято, не проверялось в этой волне.

8. Кто создаёт сегменты — вопрос остаётся открытым практически, а не только на уровне решения продукта. Ни пользовательский путь (создание сегмента на фронте), ни админский (пустая форма в Filament) сейчас не работают, поэтому появление раздела Segments в админке само по себе не отвечает на вопрос «кто» — форму ещё предстоит наполнить полями под выбранный сценарий.

9. Новое: кнопки входа «Яндекс» / «Max» / «VK» на экране авторизации — рабочая интеграция или заглушка интерфейса? Нужно уточнить у фронтенд-разработчика.
