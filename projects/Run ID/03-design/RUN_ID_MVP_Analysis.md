# RUN.ID — аналог Strava для российского рынка

Анализ MVP, функциональные блоки и agile-roadmap

Актуализация от 19.08.2026 (третья волна). Исходный анализ, roadmap и пометки первой волны (16.08.2026) сохранены без изменений там, где новых фактов не появилось. Эта волна собрана по итогам живого прогона дев-стенда в авторизованной сессии и админ-панели Filament — не по документам на Google Drive. Новая цветовая логика статуса, по запросу: **зелёный** — готово, **жёлтый** — частично / есть недоделки, **красный** — не сделано и блокирует.

## Коротко: что изменилось с прошлой волны (16.08.2026 → 19.08.2026)

Монетизация (§3, §8) — экран оформления членства полностью достроен и соответствует финальному макету: 190 ₽/месяц и 990 ₽/год, оба «разовый платёж, без автопродления». Это закрывает открытый вопрос §8 о модели платежа в пользу разового платежа на фиксированный срок, а не подписки с автопродлением. Кнопка «Перейти к оплате» теперь явно сообщает «Оплата пока недоступна» вместо того, чтобы просто ничего не делать — интеграция с ЮKassa при этом всё ещё не подключена, платёж пройти нельзя. В админке появился раздел Memberships, но список пуст и форма создания без единого поля — вручную выдать тестовое членство тоже нельзя.

Партнёрская экосистема (§3) — открытый вопрос из второй волны про «не связана админка с фронтом» снят: форма создания привилегии в Filament полностью рабочая (партнёр, название, скидка, баннер, фон, условия, промокод), на сайте 3 живые карточки с реальными данными.

Сегменты (§3) и Календарь событий (§3) — в админке появились новые разделы Segments и Events, которых раньше не было вовсе. Обе формы создания абсолютно пустые — ни одного поля, завести запись нельзя. Прогресс есть только на уровне резервирования места в структуре админки, функционально блоки остаются нулевыми.

Комплаенс и приватность (§3) — механика privacy zones на дев-стенде упростилась до одного общего слайдера радиуса (Выкл/200/400/800/1600 м) вместо двух ранее описанных режимов. Не проверялось, сохраняется ли значение на бэкенде.

Метрики и аналитика (§3) — блок «Аналитика» на детальной странице тренировки пополнился полями пульса (сред./макс.), каденса и калорий (калории пока «—»), появилась вторая интерактивная карта маршрута. Графики темпа/пульса/высоты по-прежнему отсутствуют и на стенде.

Регистрация (§2, §3) — на экране входа появились кнопки «Яндекс», «Max», «VK», отсутствовавшие ранее. Рабочая интеграция или заглушка — не проверялось.

# 2. Основные use-case'ы MVP

Статус на 19.08.2026 — уточнение: сценарий «пользователь настраивает приватную зону» реализован иначе, чем описано (единый слайдер радиуса вместо адресных зон, см. §3 ниже). Сценарий «пользователь оформляет цифровое членство» — интерфейс полностью готов, но оплата технически недоступна («Оплата пока недоступна»). Сценарий «пользователь создаёт сегмент» — по-прежнему не работает; в админке появился пустой раздел Segments, не меняющий факта. Остальные сценарии без изменений с 16.08.2026.

# 8. Дополнительные уточняющие вопросы — актуализировано 19.08.2026

Устраивает ли формат «простого разового платежа» за членство на MVP — закрыто 19.08.2026: реализованный экран оплаты прямо подписан «Разовый платёж, без автопродления» на обоих тарифах. Расхождение со статусом членства «активна до 23 апреля 2027», замеченное во второй волне, скорее всего было тестовыми данными.

Кто создаёт сегменты в MVP — не снято практически: ни пользовательский, ни админский путь создания сегмента сейчас не работают. Появление пустого раздела Segments в админке резервирует место в структуре, но не отвечает на вопрос «кто» — форму ещё предстоит спроектировать и наполнить полями под выбранный сценарий.

Нужен ли «Календарь событий» в MVP — не снято. В админке появился пустой раздел Events того же типа, что и Segments — задел нулевой функционально, несмотря на появление модели в структуре.

Новое: рабочая ли интеграция входа через Яндекс/Max/VK, появившаяся на экране авторизации, или это заглушка интерфейса — нужно уточнить у фронтенд-разработчика.

Новое: механика скрытия точек упростилась до одного общего слайдера радиуса — финальное решение фронтенда или промежуточное состояние вёрстки? Нужно сверить источник истины для бэкенд-брифа «06 Скрытие точек».
