# RUN.ID — бэкенд: админка и наполнение контентом. Что сделать

Документ для бэкенд-разработчика. Основан на прогоне админки `runid-service.devvm7.mobipark.ru/laravel/public/admin` (Laravel + Filament v5.7.6).

---

## Текущее состояние: половина ресурсов — пустые каркасы

В меню админки девять разделов: Dashboard, Activities, Events, Memberships, Partners, Places, Privileges, Segments, Users.

Проверил формы создания. Картина неоднородная:

| Ресурс | Форма создания | Данные на фронте |
|---|---|---|
| **Privileges** | полностью собрана | есть, отображаются |
| **Users** | собрана | есть |
| **Places** | **пустая — ни одного поля** | есть 5 мест |
| **Memberships** | **пустая — ни одного поля** | нет |
| **Events** | **пустая — ни одного поля** | нет |
| Partners / Segments / Activities | не проверял детально | Partners и Segments — есть |

**Главное следствие:** у `Places` на фронте отображается 5 Run-Friendly мест, но **создать или отредактировать место через админку невозможно** — форма пуста. Значит данные залиты напрямую в базу. Контент-менеджер наполнить каталог не сможет, и любая правка требует разработчика.

---

## 1. Places (Run-Friendly места) — достроить форму

**Сделать:** заполнить Filament-ресурс полями, которые уже фактически используются на фронте:
- название, адрес, координаты (широта/долгота);
- фото/логотип;
- описание — необязательное (на фронте часть карточек с описанием, часть без);
- набор тегов удобств — множественный выбор из фиксированного справочника: **Хранение вещей, Туалет, Душ, Скидка, Вода, Совместные пробежки** (ровно шесть, совпадает с фильтром на карте);
- признак активности, чтобы можно было снять место с публикации, не удаляя.

**Продумать:** способ задания координат. Ручной ввод широты и долготы для контент-менеджера неудобен и ведёт к ошибкам — стоит либо геокодировать введённый адрес автоматически, либо дать выбор точки на карте прямо в форме.

Подробности по самой сущности и по фильтрации — в документе по карте и Run-Friendly местам.

## 2. Memberships — достроить форму

Разбирается в отдельном документе по членству и оплате. Здесь фиксируется только факт: ресурс есть, форма пуста, вручную создать членство нельзя. Это мешает даже тестировать гейтинг привилегий — невозможно выдать себе подписку и посмотреть, как выглядит разблокированное состояние.

**Сделать в первую очередь:** минимальную рабочую форму (пользователь, статус, даты), даже если полноценная оплата ещё не готова. Без неё QA не может проверить ни один сценарий с активным членством.

## 4. Модель пользователя: поля, которых нет в интерфейсе

В админской карточке пользователя есть поля, отсутствующие в пользовательских настройках на фронте: **Телефон** и **Город**.

**Продумать:** это задел на будущее или недоделанный интерфейс. Если поля должны заполняться пользователем — их нет в макете настроек и надо уточнить у дизайнера. Если они только для администратора — зафиксировать это, чтобы не появились в API как редактируемые.

Также в карточке есть переключатели **«Активен»** и **«Администратор»**.

**Сделать:** проверить, что `Активен` действительно блокирует вход и доступ к API, а не является декоративным полем. Флаг блокировки, который ничего не блокирует, опаснее его отсутствия — им попробуют воспользоваться при реальном инциденте.

## 5. Права доступа в саму админку

**Сделать:**
- Убедиться, что доступ к админке ограничен флагом «Администратор», а не только знанием URL.
- Проверить, что обычный пользователь, зайдя по прямой ссылке на `/laravel/public/admin`, получает отказ.

**Продумать:** нужны ли роли внутри администраторов (контент-менеджер, который правит места и привилегии, но не трогает пользователей и членства). Для MVP скорее нет, но если админку отдадут не разработчикам — вопрос встанет сразу.

## 6. Демо- и тестовые данные

На фронте в каталоге привилегий видна карточка с названием «**Демо: страница без фона**» — очевидно технический тестовый контент.

**Сделать:** перед демонстрацией заказчику или приёмкой вычистить тестовые записи. Отдельно: в списке тренировок на стенде остались мои проверочные записи id **31**, **32**, **33** (см. документ по загрузке тренировки) — удалить, когда соответствующие дефекты будут закрыты.
