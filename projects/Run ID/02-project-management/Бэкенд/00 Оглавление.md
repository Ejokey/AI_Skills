# Бэкенд-брифы RUN.ID

Документы для бэкенд-разработчика. Пронумерованы по приоритету — порядок в папке = порядок работы.

Формат везде одинаковый: **Сделать** (конкретная работа) + **Продумать** (решения и вопросы, которые нельзя принимать самостоятельно). Всё, что проверено вживую на дев-стенде, помечено как воспроизводимое.

| # | Раздел | Состояние |
|---|---|---|
| 01 | Членство и оплата | не реализовано ничего, оплата — замкнутый круг |
| 02 | Тренировки | работает, есть подтверждённые дефекты (дубликаты, файл без GPS) |
| 03 | Админка и контент | Places, Memberships, Events — пустые каркасы без полей |
| 04 | Профиль, соцчасть, привилегии | работает, нужны серверные проверки доступа |
| 05 | Карта и Run-Friendly места | работает, семантика фильтра и карточка пина |
| 06 | Скрытие точек | не реализовано, механика подтверждена макетом |
| 07 | Уведомления | панель есть, события не заведены |
| 08 | Лента и статистика | работает, не описаны правила и агрегации |
| 09 | Календарь событий | не реализовано ни на фронте, ни в админке |
| 10 | Сегменты | фронт свёрстан целиком на моках, таблицы в БД есть, публичного API нет |

**Внешний источник:** документ фронтенда `documentation/frontend/for_backend/to_do.md` (16.08.2026) — предложенные контракты API по приватности, сегментам, поиску и описанию тренировки. При расхождении с брифами прав он: фронт уже написан под эти поля.

**Живая проверка 16.08.2026** подтвердила: футер, вкладка «Приватность» со «Скрытием точек», компактный футер на карте, дропдаун поиска с категориями «Тренировки»/«Сегменты» — всё это уже выложено на стенд и в точности соответствует доку. Заблокированные элементы (тумблер «Все тренировки», категории поиска, «Сохранить» без действия) ведут себя предсказуемо — не сломаны, а осознанно задизейблены до готовности бэка.

## Стенды

- Приложение: `runid.devvm7.mobipark.ru/frontend/local/`
- Админка (Laravel + Filament): `runid-service.devvm7.mobipark.ru/laravel/public/admin`

## Отложено осознанно

- **Награды и геймификация** — пост-MVP по решению продакта. В статистике профиля есть счётчик «Всего наград», трогать его не нужно.
- **Регистрация, вход, удаление аккаунта** — вне текущего набора документов.

## Сквозные вопросы к продакт-оунеру

Мешают оценке объёма, ответы нужны до начала соответствующих задач:

1. Промокод: одно общее поле на привилегию против обещания «используется на одном аккаунте» в макете (бриф 01).
2. Где пользователь видит цену подписки — в макетах суммы нет (бриф 01).
3. Как выдаются чеки по 54-ФЗ — скорее всего решение уже есть в АИРепортере (бриф 01).
4. Что выключает тумблер «Получать уведомления» — панель или внешние рассылки, которых пока нет (бриф 07).
5. Нужен ли календарь событий в MVP — сущность пуста с обеих сторон, макетов нет (бриф 09).
6. Мультиспорт: приоритет отдан бегу, но на стенде есть тип «Хайк», которого нет в макетах (бриф 02).
7. Кто создаёт сегменты — только администратор или пользователи тоже. Развилка, меняющая объём вдвое (бриф 10).

**Закрыто:** платёжный провайдер — **ЮKassa**, как в АИРепортере (бриф 01).
