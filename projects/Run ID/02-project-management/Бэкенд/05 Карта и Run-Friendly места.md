# RUN.ID — бэкенд: экран «Карта», Run-Friendly места. Что осталось сделать

Документ для бэкенд-разработчика. Основан на прогоне живого экрана `runid.devvm7.mobipark.ru/frontend/local/map` + сверке с макетами Figma.

**Сегменты в этот документ не входят** — по ним будет отдельный бриф. Здесь они упоминаются только там, где влияют на общее поведение карты.

**Значительная часть уже работает** и переделывать не нужно: список мест слева с фото/названием/адресом/описанием/тегами, карта справа с пинами, счётчик найденного, мультиселект-фильтр по удобствам, чипы выбранных фильтров с крестиком, связка «клик по карточке → подсветка пина и центрирование карты», сворачивание панели, переключение вкладок Run-friendly / Сегменты.

Ниже — только то, чего не хватает.

---

## 1. Семантика пустого фильтра — решить и починить

**Как воспроизвести:** открыть фильтр Run-friendly мест → «Очистить все». Результат: «Найдено: 0», список «Ничего не найдено», все пины исчезают с карты.

Сейчас логика такая: показываются места, у которых есть **хотя бы один** из выбранных тегов; ноль выбранных тегов → пустая выдача.

**Проблема:** для пользователя «я снял все галочки» читается как «не фильтровать», а не как «показать ничего». Пустой экран без объяснения выглядит как поломка, тем более что кнопка называется «Очистить все» — то есть очистить фильтр, а не очистить результаты.

**Сделать:** трактовать пустой набор тегов как отсутствие фильтрации — возвращать все места. Это стандартное поведение и оно снимает тупик, из которого пользователь не понимает, как выйти.

**Продумать:** заодно зафиксировать логику при нескольких выбранных тегах — сейчас это ИЛИ (место с любым из тегов). Альтернатива — И (место со всеми выбранными сразу). Для «найди мне место, где есть и душ, и хранение вещей» правильнее И, но при 5–24 местах это почти всегда даст пустую выдачу. Рекомендую оставить ИЛИ и зафиксировать это осознанно, а не по умолчанию.

---

## 2. Нет карточки места при клике по пину

**Как воспроизвести:** кликнуть по пину на карте. Результат: карта приближается, но никакой информации о месте не показывается.

В макете для этого есть отдельный компонент всплывающей карточки (`Bubble map`) с названием и адресом места.

**Сделать:** endpoint, отдающий данные одного места по id, чтобы фронт мог показать поповер по клику на пин. Набор полей — тот же, что в карточке списка (фото, название, адрес, теги, описание), отдельная урезанная модель не нужна.

**Продумать:** нужна ли отдельная страница места (в ранних макетах Figma такой экран был). Сейчас из карточки в списке никуда нельзя перейти — место это «конечная» сущность без детального просмотра. Если детальная страница нужна, это отдельная задача; если нет — достаточно поповера. Вопрос к продакту/дизайнеру.

---

## 3. Слои карты: сегменты не рисуются вообще

**Как воспроизвести:** переключить вкладку на «Сегменты». Результат: список слева меняется на сегменты (3 штуки), но **на карте по-прежнему только пины Run-Friendly мест**, линий сегментов нет.

То есть сейчас: Run-Friendly слой отображается всегда, слой сегментов не отображается никогда.

**Сделать (в части, касающейся Run-Friendly):** отдавать точки мест независимо от того, какая вкладка списка активна — это уже работает и это правильно, менять не нужно. Зафиксировано здесь, чтобы при добавлении сегментов случайно не привязали видимость Run-Friendly пинов к активной вкладке.

Отрисовка сегментов на карте — в бриф по сегментам.

**Ранее согласованная модель** (подтверждена в обсуждении с продактом): два слоя независимы, каждый включается своим фильтром, вкладка слева переключает только список. Оба фильтра-дропдауна на стенде уже показываются одновременно на обеих вкладках — это соответствует модели.

---

## 4. Фильтрация по геопозиции и области карты

Сейчас, судя по поведению, отдаются все места сразу, без привязки к видимой области карты или к позиции пользователя. При 5 местах это незаметно.

**Продумать:**
- Нужен ли фильтр «рядом со мной» для Run-Friendly мест. Сейчас такой чип есть **только в фильтре сегментов**, у Run-Friendly его нет. Если он нужен — потребуется принимать координаты пользователя и радиус.
- Нужна ли подгрузка по видимой области карты (bbox). Для MVP с десятками мест — не нужна, отдавать все одним запросом. Заложить в API возможность передать bbox на будущее дешевле, чем переделывать потом, но реализовывать саму фильтрацию сейчас не обязательно.

---

## 5. Наполнение и администрирование

На стенде 5 мест, в макетах фигурирует 24. Места заводит только администратор — пользовательского создания/редактирования нет и не планируется (подтверждено в UX-брифе).

**Сделать:**
- Административный способ заводить и редактировать места: название, адрес, координаты, фото, описание (необязательное), набор тегов. Форма это или сидинг-скрипт — на усмотрение, но без него контент не наполнить.
- Набор тегов зафиксирован и закрыт: **Хранение вещей, Туалет, Душ, Скидка, Вода, Совместные пробежки** — ровно шесть, совпадает с макетом. Это справочник, а не свободный ввод: место ссылается на теги, теги не дублируются строками в каждой записи.

**Продумать:** тег «Скидка» смысловым образом близок к привилегиям партнёров, но это **разные сущности** — ранее продакт зафиксировал, что Run-Friendly места и партнёрские привилегии на MVP не пересекаются. Не связывать их в модели данных и не пытаться переиспользовать сущность привилегии для тега «Скидка».

## 6. Кнопка «Новый маршрут» — нефункциональная заглушка

**Как воспроизвести:** нажать «Новый маршрут» в правом верхнем углу карты. Результат: ничего не происходит.

Создание маршрутов ранее было отнесено к пост-MVP. Кнопка при этом отрисована и кликабельна, что для пользователя выглядит как баг.

**Сделать:** решение продакта — либо скрыть кнопку до реализации, либо оставить с явной заглушкой («скоро»). Бэкенд-задачи под маршруты сейчас не брать.

---

## 7. Пагинация списка

Список сейчас отдаётся целиком и скроллится. При десятках мест это нормально.

**Продумать:** предусмотреть лимит на количество возвращаемых записей в API, чтобы при росте базы ответ не разрастался бесконтрольно. Полноценную постраничную навигацию в MVP не делать.
