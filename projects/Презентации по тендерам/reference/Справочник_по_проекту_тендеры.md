## 3. Правила содержания слайдов (обязательно соблюдать)

- Переносы строк — только на границе предложения, не посреди фразы.
- Избегать формулировок вроде «целевая для вас CMS» и явной привязки текста слайдов к критериям тендера.
- Формулировки про санкции/штрафы — минимальные и без жирного выделения.
- Названия NDA-клиентов — держать в абстрактном виде (без прямого указания).
- Финансовые цифры менять **только по явному указанию** — никогда самостоятельно.
- Стратегические добавления (новый скоуп, рекомендации) — **только после явного одобрения**, не вставлять по своей инициативе.
- Принцип минимального вмешательства: редактировать только то, что явно запрошено; нетронутые слайды должны оставаться байт-в-байт идентичными.

## 4. Технический pipeline

### PDF-пайплайн (HTML → PDF)
- Стек: Python `build.py` (генератор HTML-слайдов) → Playwright headless Chromium (1280×720px, `print_background=True`) → `pypdf` / `fitz` (PyMuPDF) для вставки ссылок и работы со страницами.
- Все ассеты — base64 в `img.json` для самодостаточного рендеринга HTML. После добавления новых картинок — перекодировать и перезагрузить.
- Проверка переполнения (overflow) должна мериться **от верхнего края футера**, а не от низа слайда.
- При изменении количества слайдов синхронно обновлять три вещи: `footer(n, total=N)`, номера страниц в оглавлении (TOC), и `page_ranges='1-N'` в `render.py`.
- DPI-рассинхрон логотипов даёт «сплющивание» — чинится обрезкой пустых полей и заданием `height: Xpx; width: auto`.
- `object-position: top` — сохраняет шапку при cover-обрезке высоких скриншотов.

### PDF-редактирование (PyMuPDF/fitz)
- Некоторые `.docx`/`.pdf` на деле — ZIP-архивы с нумерованными `.txt`/`.jpeg` файлами внутри → использовать `zipfile.ZipFile`, а не `pypdf`/`python-docx`.
- Кириллические имена файлов ломают некоторые Python-библиотеки → копировать в `/tmp/w/` с ASCII-именами перед обработкой.
- Декоративные «блобы»/подложки нужно извлекать через `fitz.Pixmap` + SMask для корректного RGBA-альфа-канала (`extract_image()` теряет прозрачность).
- Именованные PDF-ссылки (named destinations) теряются при `insert_pdf()` → пересобирать вручную через `insert_link({'kind': fitz.LINK_GOTO, ...})`.
- Базовые шрифты (helv, hebo) не умеют в кириллицу → использовать Liberation Sans TTF (`/usr/share/fonts/truetype/liberation/`).
- Замена текста в футере требует `fitz.Font(fontfile=TTF_PATH)` с `.text_length()` для корректного измерения кириллицы.
- Надёжная замена страницы — через `show_pdf_page()` + `update_stream(x, b" ")`; избегать `delete_page`/`insert_page` (сдвигают индексы).

### PPTX
- `pptxgenjs` (Node.js), масштаб px→inches: `S = 13.333/1280`.
- Внутренние ссылки между слайдами — через `{slide: N}`.

### Прочие инструменты
- QA/проверка: `pdftoppm` для извлечения слайдов, `tesseract` для OCR-верификации, когда просмотрщик изображений не справляется.
- Excel: `openpyxl` с повторным объединением merged-ячеек после записи; `recalc.py` (`/mnt/skills/public/xlsx/scripts/recalc.py`) для пересчёта формул.
- Шрифты: Manrope (кириллица, бренд Интер РАО), Liberation Sans (общая кириллица в PDF).
- Все финальные файлы — в `/mnt/user-data/outputs/`.

## 5. Подход к работе (для агентов)

1. **Итеративная валидация по скриншотам** — референсные скриншоты задают пиксель-точный стандарт; перед сдачей — программная проверка overflow/выравнивания.
2. **Минимальное вмешательство** — менять только явно запрошенное; о стратегических решениях — сообщать, а не решать самому.
3. **Двухбрендовая структура** — КП подаются либо от SNAgency, либо от AIR, в зависимости от тендера; портфолио и руководитель по коммерции — общие.
4. **Согласование текста перед рендером** — для новых колод сначала готовится текстовая/markdown структура на утверждение, и только потом — вёрстка.
5. **Точечные правки** — короткие сообщения со ссылкой на конкретный номер слайда и точную формулировку — стандартный формат запросов.
