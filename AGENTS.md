# AGENTS.md — операционная инструкция агентной системы

Этот файл — точка входа. Любой ИИ-агент, получивший доступ к этой папке, читает его первым
и после этого способен работать как часть системы. Файл написан tool-agnostic: он не
предполагает конкретный ИИ-инструмент.

---

## 1. Что это за репозиторий

Операционная база одного человека (Владислав), который закрывает роли PM, BA, маркетолога,
дизайнера, пресейла и тендерного специалиста для двух связанных юрлиц — **SNAgency** и **AIR**.

Основная работа: подготовка тендерных заявок, коммерческих предложений (КП), презентаций
и смет для проектов веб-разработки, digital-маркетинга и внедрения ИИ-решений.

Три вида содержимого, и разница между ними принципиальна:

| Папка | Что это | Как часто меняется | Кто правит |
|---|---|---|---|
| `memory/` | **Факты**: контакты, цены, решения, накопленные правила | Постоянно, в процессе работы | Агент — по протоколу в §7 |
| `skills/` | **Методология**: как выполнять работу | Редко | Человек, осознанно |
| `tenders/` | **Тендеры**: основной рабочий процесс, стадии в структуре папок | Постоянно | Оба |
| `projects/` | **Прочее**: продуктовая работа, общие ресурсы, старые тендеры | Постоянно | Оба |

Если факт из `memory/` противоречит тексту в `skills/` — **прав `memory/`**. Скиллы описывают
метод, память описывает текущую реальность.

Тендерная работа — основная. Под неё выделен пайплайн со своей структурой папок (§3).
Папки тендеров в `projects/` — работа до введения пайплайна; переносятся в `tenders/`
по мере возвращения к ним, не все сразу.

## 2. Протокол входа

В начале любой задачи, по порядку:

1. **Этот файл** — целиком.
2. **`memory/INDEX.md`** — оглавление памяти. Оттуда открой те файлы памяти, которые
   относятся к задаче. Всю память подряд грузить не надо.
3. **Если задача тендерная:** `tenders/PROCESS.md`, затем `tenders/<Тендер>/STATUS.md`.
   Без `STATUS.md` не начинай — там состояние, паспорт и что уже сделано.
4. **Если задача про клиента вне тендеров:** `projects/<Клиент>/CONTEXT.md`, если есть.
5. **Нужный скилл** — по таблице маршрутизации в §5. Скилл читается тогда, когда дошёл
   до соответствующей работы, а не заранее.

Не начинай работу, пропустив шаги 1–2. Большая часть ошибок в этой системе — это агент,
который действовал по общему знанию вместо того, чтобы прочитать зафиксированные правила.

## 3. Тендерный пайплайн — основной процесс

Полное описание — **`tenders/PROCESS.md`**. Читай его перед любой тендерной задачей.

Структура папок повторяет процесс: одна стадия — одна папка.

```
tenders/<Тендер>/
├── STATUS.md          ← состояние, паспорт, решения, лог. Читается первым
├── 00-source/         ← документация как пришла, НЕ редактируется
├── 01-analysis/       ← разбор, вывод об участии
├── 02-estimate/       ← расчёты: внутренний + клиентский
├── 03-proposal/       ← КП, презентация
└── 04-application/    ← формы, документы заявки
```

| № | Стадия | Агент | Обязательна |
|---|---|---|---|
| 0 | Приёмка документации | `tender-intake` | да |
| 1 | Анализ участия | `tender-analyst` | по необходимости |
| 2 | Деньги | `tender-estimate` | по необходимости |
| 3 | КП и презентация | `tender-deck` | обычно да |
| 4 | Документы заявки | `tender-docs` | по необходимости |
| R | Проверка перед отправкой | `tender-reviewer` | рекомендуется перед показом заказчику |

Стадия R не входит в основную нумерацию и не привязана к одному моменту — вызывается
после любой из стадий 2–4, когда результат готов к показу заказчику или человеку.

**`STATUS.md` — центральный файл.** Агент стартует без контекста разговора, поэтому
состояние тендера живёт в файле, а не в переписке. Читается первым, обновляется после
каждой стадии. Пропуск стадии фиксируется строкой «пропущено, причина» — молча пропускать
нельзя.

**Возврат к любой стадии возможен в любой момент.** После правки, затрагивающей другие
стадии, оркестратор обязан проверить связанное по разделу «Зависимости» в `STATUS.md`
и сказать человеку о рассинхроне (изменилась смета → цифры в КП устарели).

## 4. Роли и агенты

Оркестратор — сессия, в которой человек ведёт разговор. Он не выполняет специализированную
работу сам, а передаёт её агенту, если задача попадает в чью-то зону.

Агент стартует **без контекста разговора**. Всё, что ему нужно — путь к папке тендера,
конкретная задача, что уже сделано — оркестратор передаёт явно в задании.

| Агент | Когда вызывать | Скилл | Результат |
|---|---|---|---|
| `tender-intake` | Пришли файлы по тендеру, «заведи тендер», разбор Telegram | — | Папка тендера + `STATUS.md` + опись |
| `tender-analyst` | «Стоит ли участвовать», разбор требований, риски | `tenders/rfp-responder` | `01-analysis/ЗАКЛЮЧЕНИЕ.md` |
| `tender-estimate` | Смета, НМЦ, обоснование цены, прикидка | `tenders/tender-estimate-builder` | Внутренний расчёт + клиентская смета |
| `tender-deck` | КП, презентация, слайды, правки колоды | `tenders/tender-kp-builder` | PDF/PPTX + открытые вопросы |
| `tender-docs` | Состав заявки, формы, комплектность | `tenders/rfp-responder` | Чек-лист + заполненные формы |
| `tender-reviewer` | Проверка готового артефакта перед показом заказчику, чек-лист типовых ошибок | — | Список нарушений, ничего не правит |
| `business-analyst` | БТ, ФТ, use cases, user stories, схемы | `business-analysis/*` | Документ в папке проекта |
| `research` | Анализ конкурентов, рынка, аудитории | `marketing/*`, `shared/deep-research` | Отчёт + источники |

Роли без выделенного агента (`sales/`, `design/`) оркестратор ведёт сам через скиллы —
это диалоговая работа, делегировать её нечего.

Кто на какой модели работает и как это менять — `.claude/agents/MODELS.md`.
Стадии 0–2 переведены на модель попроще; это замер, откат в одну команду.

**Когда уместен `/loop`:** повторяющаяся проверка — отслеживание дедлайна, мониторинг
ответов заказчика на разъяснения, итеративная доводка вёрстки. Не для генерации
содержания: КП не улучшается от пяти переписываний без обратной связи человека.

## 6. Границы самостоятельности

Жёсткие. Нарушение обесценивает любую техническую аккуратность, потому что документы
здесь имеют юридические и финансовые последствия.

**Различай инициативу агента и явное указание человека.** Если человек сам назвал
конкретное значение или действие («поставь 8000 ₽/мес», «добавь пункт про поддержку») —
это выполнение указания, делай сразу. Границы ниже — про то, что агент придумывает **сам**.

Агент **никогда не придумывает сам**:

| Что | Почему | Что делать вместо |
|---|---|---|
| Цены, ставки, суммы | Зависят от маржи и условий, которых у агента нет | Спросить точное значение |
| Новые пункты скоупа, услуги, гарантии | Это коммерческое обязательство | Предложить в чате, дождаться «да» |
| Сроки, условия оплаты | То же самое | Уточнить |
| Правки, о которых не просили | Ломает согласованную вёрстку и требует лишнего цикла проверки | Оставить байт-в-байт |

Если ключевая цифра нужна, а указания не было — **не подставляй правдоподобное значение
и не ставь заглушку молча**. Скажи прямо: нужна цифра от руководителя.

**Правило минимального касания:** просят поправить слайд 7 — меняется только слайд 7.
Замеченную опечатку на слайде 9 назови отдельно, но не правь.

## 7. Протокол памяти

Память обновляется **в процессе работы**, иначе она мертва. Но не всё подряд, иначе она
превращается в свалку.

### Когда писать

Тест одним вопросом: **«будет ли это важно через 3 месяца на другом проекте?»**

- Да → в память
- Нет (разовая инструкция, деталь текущей задачи) → не писать

Триггеры, по которым почти всегда надо писать:

1. Человек поправил агента и объяснил, как правильно → правило
2. Человек назвал цифру, ставку, условие, которое будет повторяться → факт
3. Принято решение, которое дальше будет влиять на работу → лог решений
4. Выяснилось что-то про клиента, чего нет в файлах проекта → контекст проекта

### Куда писать

| Что | Файл |
|---|---|
| Правило, применимое ко всем проектам | `memory/rules.md` |
| Юрлица, контакты, портфолио, бренды | `memory/company.md` |
| Ставки, параметры ценообразования | `memory/pricing.md` |
| Решение с датой и причиной | `memory/log.md` |
| Факт или решение по конкретному тендеру | `tenders/<Тендер>/STATUS.md` |
| Факт про клиента вне тендеров | `projects/<Клиент>/CONTEXT.md` |

**Не путай уровни.** «Заказчик не отвечает на разъяснения» — факт этого тендера,
идёт в `STATUS.md`. «Не показываем клиенту почасовую ставку» — правило для всех,
идёт в `memory/rules.md`. Правило, записанное в `STATUS.md`, потеряется на следующем тендере.

### Как писать

- Одна запись = один факт. Не абзацами.
- Дата в абсолютном виде (`2026-08-06`), не «на прошлой неделе».
- Перед записью проверь, нет ли уже такого факта — обнови существующий, а не плоди дубль.
- Если факт устарел и стал неверным — удали его, не оставляй рядом с новым.
- **После записи скажи человеку одной строкой, что записал.** Он должен иметь возможность
  отменить.

### Чего в памяти быть не должно

Того, что уже есть в файлах и восстанавливается чтением: структура проекта, содержание
документов, история git. Память — про то, что иначе потеряется.

## 8. Куда складывать результаты

| Что | Куда |
|---|---|
| Всё по конкретному тендеру | `tenders/<Тендер>/<стадия>/` — см. §3 |
| Состояние тендера | `tenders/<Тендер>/STATUS.md` |
| Скриншоты портфолио | `projects/Презентации по тендерам/portfolio-screenshots/<Компания>/` |
| Логотипы, ассеты для вёрстки | `projects/Презентации по тендерам/assets/` |
| Общие справочники по тендерам | `projects/Презентации по тендерам/reference/` |
| Юридические документы компании | `projects/_Компания/` |
| Нетендерная работа по клиенту | `projects/<Клиент>/` |

Ресурсы, общие для всех тендеров (портфолио, логотипы, юрдокументы), лежат в `projects/`
и **не дублируются** внутрь папок тендеров — на них ссылаются.

Внутри стадии тендера иерархию не углублять: плоская структура здесь сознательна.

## 9. Формат общения

Человек предпочитает короткие конкретные ответы:

- сделал X → вот файл → вот что осталось открытым
- открытые вопросы — нумерованным списком, а не растворённые в тексте
- при неопределённости — один точный вопрос, а не список из пяти

Не работает: пересказ проделанной работы, объяснение очевидного, непрошеные предложения
улучшений.
