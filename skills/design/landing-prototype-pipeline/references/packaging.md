# Упаковка результата для отправки заказчику

Конвертация, выгрузка, загрузка на Диск. Плюс главное ограничение коннектора,
из-за которого нельзя просто «залей всё на Drive».

---

## Состав пакета

| Файл | Зачем |
|---|---|
| Сопроводительное письмо | Задаёт рамку прочтения. Без него получатель не знает, с чего начать |
| Тексты | Полные тексты всех версий с альтернативами заголовков и открытыми вопросами |
| Статичная выгрузка макетов (PDF) | На случай, если Figma не откроют |
| Смета / расчёт | Как есть |
| Ссылка на файл макетов | С доступом на уровне, который требует задание |

⚠️ **Перед отправкой проверить уровень доступа к файлу макетов.** Если задание требует
комментирования — «Может комментировать» по ссылке. Это не выставляется само.

### Что в сопроводительном письме

1. Состав пакета таблицей
2. Чем версии отличаются по конструкции, а не по оформлению
3. Откуда взята фактура (и что ничего не додумано)
4. Техническая обвязка: разметка, аналитика, интеграции
5. **Что требуется от заказчика** — нумерованным списком
6. Сроки и вехи со ссылкой на смету

## Markdown → DOCX

`python-docx`. Pandoc в окружении обычно нет — не рассчитывай на него.

Конвертер должен уметь: заголовки 1–3, таблицы с заливкой шапки, цитаты с левой линейкой,
маркированные и нумерованные списки, инлайн `**bold**` / `*italic*` / `` `code` `` / ссылки,
горизонтальные линейки.

Ключевые моменты:

```python
st = doc.styles['Normal']
st.font.name = 'Calibri'
st.element.rPr.rFonts.set(qn('w:eastAsia'), 'Calibri')   # иначе кириллица подменяется
st.element.rPr.rFonts.set(qn('w:cs'), 'Calibri')
```

- Заливка ячейки — только через OXML: `w:shd` с `w:fill`
- Таблица определяется по строке `|…|` со следующей строкой-разделителем `|---|`
- Не добавляй титул параметром, если в markdown уже есть `# Заголовок` — получишь дубль
- Проверяй результат: `len(doc.paragraphs)`, `len(doc.tables)` и первые абзацы

Готовый рабочий конвертер собирался в этом пайплайне дважды — держи его в scratchpad
проекта, а не переписывай с нуля.

⚠️ Не правь python-файлы через `sed` с экранированием — ломает первую строку и кодировку.
Перезаписывай файл целиком.

## Макеты → PDF

```
download_assets(fileKey, nodeId, defaultFormat='pdf')
```

Даёт векторный PDF одного фрейма — текст остаётся текстом. Ссылка живёт минуты,
качать сразу через `curl -sL -o`.

Склейка в один документ с закладками:

```python
from pypdf import PdfWriter, PdfReader
w = PdfWriter()
for f, title in zip(files, titles):
    for p in PdfReader(f).pages: w.add_page(p)
    w.add_outline_item(title, len(w.pages)-1)
for p in w.pages:
    try: p.compress_content_streams()
    except Exception: pass
```

Каждый вызов `download_assets` тратит квоту MCP. Восемь фреймов — восемь вызовов,
это почти половина суточного лимита Starter. Планируй.

Итоговый размер: страница десктопа с фотографиями ≈ 5–6 МБ, шесть страниц ≈ 25 МБ.

## Загрузка на Google Диск

**Главное ограничение: коннектор принимает содержимое только параметром.**
Бинарный файл идёт base64 через переписку. Файл 85 КБ — это примерно 60k токенов
(прочитать + отправить). Для PDF на 25 МБ путь закрыт полностью.

Что из этого следует:

| Файл | Как |
|---|---|
| Небольшой `.docx` / `.xlsx` | Можно base64, но считай цену заранее |
| Документ, который будут комментировать | Лучше HTML → Google Doc: дешевле и сразу комментируемо |
| PDF, архивы, крупные бинарники | Отдавать локально, человек кладёт сам |
| Файл, который уже есть на Диске | `copy_file` — один вызов, ничего не передаётся |

HTML → Google Doc: `create_file` с `textContent` и `contentMimeType: 'text/html'`,
конверсию не отключать. Заголовки, таблицы, списки и жирный сохраняются.

Порядок действий:
1. Найти родительскую папку: `search_files` с `title contains … and mimeType = 'application/vnd.google-apps.folder'`
2. Создать подпапку: `create_file` с `contentMimeType: 'application/vnd.google-apps.folder'` и `parentId`
3. Загрузить содержимое в неё

⚠️ Перед копированием файла, который уже лежит на Диске, спроси, актуальна ли та версия.
Одноимённый файл там часто оказывается более старым, чем локальный.

## Побочная оптимизация: xlsx раздут пустыми строками

Файлы, сохранённые из редакторов, часто содержат тысячу размеченных пустых строк.
Обрезка даёт 2–3-кратное уменьшение без потери содержимого:

```python
wb = openpyxl.load_workbook(src)
for ws in wb.worksheets:
    used=[i for i,r in enumerate(ws.iter_rows()) if any(c.value is not None for c in r)]
    last=(max(used)+1) if used else 1
    if ws.max_row > last: ws.delete_rows(last+1, ws.max_row-last)
wb.save(dst)
```

**Обязательно сверить после**: количество строк с данными, число заполненных ячеек и
объединений по каждому листу. Оригинал не перезаписывать — класть рядом.

На реальном файле: 85 КБ → 32 КБ при полностью идентичном содержимом.
