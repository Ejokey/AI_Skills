# Пайплайн: лендинг / прототип / макет

Восстановлен из реального прогона (АО «Медицина», прототипы A/B-тестирования, 2026-08-11):
6 макетов × 2 брейкпоинта, тексты, микроразметка, упаковка для заказчика.

Порядок стадий не декоративный. Каждая перестановка ниже уже приводила к переделке.

---

## 0. Вход: что выяснить до первой строки

Не начинай ни с текстов, ни с вёрстки, пока не ответил:

| Вопрос | Почему это блокирует |
|---|---|
| Одно целевое действие страницы | Определяет структуру целиком, а не только кнопку |
| Есть ли живой сайт/бренд заказчика | Меняет источник палитры, шрифта и фактуры |
| Кто даёт изображения | Ноль изображений на бренд-странице — дефект, а не сдержанность |
| Десктоп + мобайл или только десктоп | Общее правило `memory/rules.md` — только десктоп; ТЗ может это перекрыть, тогда перекрывает |
| Инструмент сдачи | Figma / HTML / PDF — от этого зависит вся сборка |

Если задание пришло документом — разбери его буквально: там обычно перечислен обязательный состав (блоки, форматы, разметка), и по нему потом принимают работу.

## 1. Фактура: собрать с живого сайта, а не выдумать

**Правило: ни одной цифры от себя.** Цены, стаж, лицензии, режим работы, документы — только из источника.

Палитру и шрифт снимай инструментально, не на глаз:

```js
// в браузере на странице заказчика
const c={};document.querySelectorAll('a,button,div,span,h1,h2,header').forEach(e=>{
  const s=getComputedStyle(e);[s.backgroundColor,s.color].forEach(v=>{
    if(v&&v!=='rgba(0, 0, 0, 0)')c[v]=(c[v]||0)+1;});});
Object.entries(c).sort((a,b)=>b[1]-a[1]).slice(0,15);
```

Частотность даёт основной цвет, цвет текста, поверхности. Плюс `getComputedStyle(document.body).fontFamily`.

Там же собери **реальные изображения заказчика** — фото сотрудников, продукта, результатов. Свой контент клиента всегда лучше стока и лучше серого прямоугольника. Проверь `img` с `naturalWidth > 150`, забирай по `alt`.

⚠️ **Изображения людей и любые «до/после» требуют согласия.** Даже если они уже опубликованы у заказчика. Ставь — но с явной пометкой в макете и в списке открытых вопросов.

## 2. Тексты — до вёрстки

Скилл: **`copywriting`**.

Правило `memory/rules.md`: сначала текст, потом вёрстка. Markdown на согласование, и только после «ок» — сборка. Верстать до утверждения текста значит гарантированно переверстывать.

Что обязательно в текстовом документе:
- 2–3 альтернативы каждого H1 с обоснованием, какой рекомендуешь и почему
- Формула CTA: `[глагол] + [что получит] + [уточнение]`. Не «Отправить», а «Получить чек-лист»
- Специфика вместо общих слов: «10 810 ₽», а не «доступные цены»
- Сводная таблица отличий версий, если версий несколько
- Нумерованный список открытых вопросов к заказчику
- Отраслевые дисклеймеры (медицина, финансы, БАДы — обязательны по закону)

Демо-контент помечай явно: `[ДЕМО]`. Отзывы, которых нет, — самая частая причина, по которой потом переделывают.

## 3. UX-структура и визуальная система

Скиллы: **`web-design-expert`** (деревья решений по типу задачи) и **`impeccable`** — обязательно прочитать регистр: `reference/brand.md` для лендинга, `reference/product.md` для интерфейса.

Что взять оттуда и применить сразу, а не на ревью:
- Длина строки **65–75 знаков**. На десктопе колонку текста ограничивать 680–720 px, не растягивать на 1280
- Контраст **4.5:1** для основного текста, 3:1 для крупного. Приглушённый серый для дисклеймеров — самая частая ошибка
- Тач-таргет **≥44 px**, на мобильных ставить sticky-панель с основным действием
- Шкала кегля: **7–8 ступеней с шагом ≥1.25**. Восемнадцать ступеней с шагом 6% — это не система
- Карточные сетки — не единственная форма. Восемь одинаковых сеток подряд = страница читается одной текстурой

Мобильная версия — не десктоп в одну колонку. Порядок блоков пересобирается: то, ради чего человек пришёл, поднимается вверх.

## 4. Сборка в Figma

Скилл: **`figma-use`** (обязателен перед любым вызовом `use_figma`).

**Читай `references/figma-build.md` целиком до первого скрипта.** Там ловушки Plugin API, каждая из которых стоила отдельного цикла: белая заливка у контейнеров по умолчанию, обрезка текста после `resize`, рваная высота карточек, недоступность Dev Mode аннотаций.

Порядок:
1. Инвентаризация файла (read-only): страницы, существующие компоненты, переменные
2. Коллекция токенов из палитры со стадии 1
3. Пустые фреймы-заготовки, спозиционированные на канвасе
4. Наполнение по одному фрейму за вызов, скриншот после каждого
5. Обложка «О файле»: состав, условные обозначения, открытые вопросы

**Квота Figma MCP на плане Starter ≈ 20 вызовов на окно, окно похоже на суточное.** Копирование файла внутри того же аккаунта лимит не сбрасывает — считается на команду. Планируй сборку пачками: один вызов = один смысловой кусок, а не одна правка.

## 5. Аннотации и техническая обвязка

Если задание требует микроразметку, аналитику, интеграции — вынеси это отдельным фреймом-документом: карта внедрения по блокам, готовые примеры кода, порядок валидации.

Отдельно фиксируй **чего быть не должно**: разметка отзывов, которых нет; `Offer` при цене диапазоном. Это отличает работу от шаблона.

Каждый блок в макете подписывай типом разметки, который в него внедряется.

## 6. Проверка до показа человеку

Скилл: **`impeccable`**, команда `critique` (регистр brand) или `audit`.

Плюс собственный прогон — см. `references/quality-gates.md`: автопроверка обрезанного текста, нулевой ширины, белых обёрток на тёмном, консистентности телефонов и цен по всем фреймам, плюс расчёт контраста и длины строк.

**Сверь текстовый документ с макетом.** Расхождения, которые всплывают именно здесь:
- Нумерация блоков в документе ≠ номера секций в макете
- Блоки, добавленные в макет на поздней стадии, не попали в тексты
- Смета обещает данные, которых у заказчика нет

## 7. Разбор с человеком

Скилл: **`grilling`**.

Спорное — спрашивать, очевидное — править. Вопросы задавать раундами: сначала корневые развилки, потом зависимые от них. Иначе чинишь то, что человек хотел сделать иначе.

## 8. Упаковка для отправки

Состав пакета: сопроводительное письмо, тексты, статичная выгрузка макетов, смета/расчёт.

**Сопроводительное письмо задаёт рамку прочтения:** что в пакете, как устроены версии, что требуется от заказчика, сроки. Без него получатель не понимает, с чего начать.

Технические детали конвертации и выгрузки — `references/packaging.md`.

⚠️ **Загрузка бинарников через Google Drive-коннектор идёт base64 через переписку.** Файл на 85 КБ — это ~60k токенов на чтение и отправку. Для больших файлов не годится: либо отдавай локально и человек кладёт сам, либо конвертируй в Google Doc из HTML (дешевле и даёт комментирование).

## Границы

Действуют §6 `AGENTS.md`. Дополнительно для этой работы:

- **Цены, сроки, гарантии** в текстах страницы — только из источника или от человека
- **Компетенцию, которой нет, не заявляем** — но и об отсутствии не пишем
- **Правило минимального касания**: просят поправить блок 7 — меняется блок 7
- **Юридические дисклеймеры не сокращаем и не прячем** в самый нечитаемый цвет

## Чек-лист перед сдачей

- [ ] Все цифры прослеживаются к источнику
- [ ] Демо-контент помечен, открытые вопросы выписаны списком
- [ ] Контраст основного текста ≥4.5:1, дисклеймеров — тоже
- [ ] Длина строки 65–75 знаков на десктопе
- [ ] Тач-таргеты ≥44 px, мобильный порядок блоков пересобран
- [ ] Обрезанного текста нет (см. quality-gates)
- [ ] Текстовый документ и макет не противоречат друг другу
- [ ] Доступ к файлу открыт на уровне, который требует задание (комментирование)
