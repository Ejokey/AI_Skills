# Пайплайн сборки колоды HTML → PDF

Стек: Node.js `build.js` (генерирует `deck.html`) → Playwright headless Chromium
(1280×720) → `render.js` (скриншот каждого слайда + отчёт о переполнении + PDF).

Каждая ловушка ниже однажды стоила отдельного цикла правок.

---

## 1. Кириллица в путях: сборочные скрипты в ASCII-папке

**Проблема.** Bash/shell на этой машине не обрабатывает кириллицу в путях надёжно —
кодировка бьётся в слое проверки прав, команда не доходит до исполнения.

**Решение.** Скрипты сборки лежат в ASCII-папке в корне репозитория — `_deckbuild/`,
а результат пишется в папку проекта с кириллическим именем. Сам Node.js кириллицу
в путях обрабатывает нормально — проблема только в оболочке.

```
_deckbuild/
├── build_<клиент>.js      ← генератор deck.html
├── render_<клиент>.js     ← Playwright: скриншоты + отчёт + PDF
├── prep_<клиент>.js       ← ассеты в base64 → img.json
├── make_white_logo.js     ← белая версия логотипа (см. §6)
└── css.txt                ← общий CSS-шаблон дек AIR
```

**Запускать из ASCII-корня репозитория:**

```bash
cd "C:\Users\Vladislav\Desktop\Claude folder" && node _deckbuild/build_2b.js && node _deckbuild/render_2b.js
```

Критично: `cwd` должен быть ASCII-корнем. Если предыдущей командой сделали `cd`
в кириллическую папку, у Node ломается разрешение модулей — вернись в корень.

**Извлечение текста из исходников** (docx, pdf) — вывод писать в UTF-8 файл, не в консоль:
Windows-консоль в cp1251 падает на кириллице и на «₽».

```python
# .docx
import zipfile, re
xml = zipfile.ZipFile(path).read('word/document.xml').decode('utf8')
txt = re.sub(r'<[^>]+>', '', re.sub(r'</w:p>', '\n', xml))
open('_deckbuild/out.txt', 'w', encoding='utf8').write(txt)
```

Если файл не находится по имени из-за кодировки — ищи через `os.listdir()`
с фильтром по `os.path.getsize()`.

## 2. Отчёт о переполнении

Главный инструмент контроля вёрстки. `render.js` обходит все `.slide`, считает нижнюю
границу контента и сравнивает **с верхним краем футера**, а не с низом слайда — это
частая ошибка: слайд визуально «влезает», но текст лезет под футер.

```js
const report = await page.evaluate(() => {
  return [...document.querySelectorAll('.slide')].map((slide, i) => {
    const top = slide.getBoundingClientRect().top;
    const footer = slide.querySelector('.footer');
    const footerTop = footer
      ? footer.getBoundingClientRect().top - top
      : slide.getBoundingClientRect().height;
    let bottom = 0;
    slide.querySelectorAll('*').forEach((el) => {
      if (el.classList.contains('footer')) return;
      const b = el.getBoundingClientRect().bottom - top;
      if (b > bottom) bottom = b;
    });
    return { n: i + 1, bottom: Math.round(bottom), footerTop: Math.round(footerTop),
             overflow: bottom > footerTop + 1 };
  });
});
```

Печатает по строке на слайд: `слайд 04: низ=580px, футер=673px -> ok`.

**Читай отчёт, а не смотри на глаз.** И наоборот — отчёт не ловит разъехавшиеся колонки,
ragged-края и дубли: **скриншоты надо смотреть глазами**.

## 3. Пустота внизу слайда

Пустая нижняя треть — дефект вёрстки, не нейтральное состояние. Возникает всегда после
сокращения контента (объединили модули, убрали блок).

Ориентир: низ контента не выше ~80% расстояния до футера. Т.е. при футере 673px
контент должен доходить примерно до 540–600px.

Как добирать, по порядку предпочтения:

1. Крупнее текст и заголовки в блоках (13 → 14px в списках, 38 → 44px у цены)
2. Больше внутренних паддингов и зазоров между пунктами
3. Опустить блок ниже (`margin-top` на обёртке)
4. Добавить содержательную плашку-вывод под основным блоком

Не растягивать блок на всю высоту через `flex: 1` — получится пустота **внутри** карточек,
что хуже, чем пустота под ними.

## 4. Ловушки флексбокса

**`min-height: 0` на вложенных flex-колонках.** Без него Chromium не даёт дочернему
элементу с `flex: 1 1 auto` реально растянуться по высоте родителя. Симптом: контент
прижат к верху, под ним пустота, хотя стоит `justify-content: center`.

```css
.body { flex: 1; display: flex; flex-direction: column;
        justify-content: space-between; min-height: 0; }
```

**`space-between` при малом контенте рвёт слайд посередине** — весь остаток высоты
уходит в зазор между блоками. Для пары «содержательный блок + плашка-вывод»:

```css
.body:has(> .cards + .callout) { justify-content: flex-start; gap: 24px; }
.body:has(> .cards + .callout) > .cards { flex: 0 0 auto; }
```

Пустой низ слайда выглядит нейтрально, пустота **посередине** читается как брак.

**Для короткого КП** большинство контентных слайдов проще держать на `flex: 0 0 auto`
(контент по своей высоте, прижат под заголовок), чем центрировать.

## 5. Выравнивание однотипных блоков

**Две таблицы рядом разъезжаются.** `width: 16%` на первой колонке браузер игнорирует
при auto-layout, и колонки встают по длине подписей — у таблицы с длинными подписями
данные сдвинуты правее. Лечится:

```html
<table style="width:100%; border-collapse:collapse; table-layout:fixed">
  <tr><td style="width:128px"></td>  <!-- фиксированная колонка подписей -->
```

**Карточки в ряд выравниваются и по верху, и по низу.** Если у карточек разной длины
описания, `margin-top: auto` на нижнем блоке выровняет низ, но верх пойдёт вразнобой.
Правильно: зафиксировать высоту выравнивающего элемента и дать нижнему блоку расти.

```html
<div style="...; min-height:96px">${desc}</div>          <!-- одинаковая высота -->
<div style="...; flex:1 1 auto">${painsBlock}</div>       <!-- добирает остаток -->
```

## 6. Логотип на тёмных слайдах

**Проблема.** `logo_air.png` в `img.json` — на самом деле **JPEG с непрозрачным белым
фоном**, а не PNG с альфой. Поэтому:

- `filter: brightness(0) invert(1)` даёт сплошной белый прямоугольник;
- `filter: invert(1); mix-blend-mode: screen` даёт бледный прямоугольник вокруг знака —
  JPEG-шум по краям текста не даёт чистого чёрного.

**Решение — сгенерировать честный PNG с альфой** пиксельным threshold'ом
(`_deckbuild/make_white_logo.js`, использует уже установленный Playwright):

```js
const lum = 0.299*px[i] + 0.587*px[i+1] + 0.114*px[i+2];
let alpha = 255 - lum;      // тёмный знак → непрозрачный
if (alpha < 8) alpha = 0;   // срезаем остаточный JPEG-шум фона
px[i] = px[i+1] = px[i+2] = 255;
px[i+3] = alpha;
```

Кладётся в `img.json` как `logo_air_white.png` и используется на тёмных слайдах:

```css
.slide.dark .logo-badge { background: none; padding: 0; }
.slide.dark .logo-badge img { height: 58px; }
```

**Размер.** Исходник 504×140. На высоте 58px это ~2,4× плотности пикселей — качество
не теряется. Выше ~70px начнёт мылить.

**В коротком КП логотип только на титуле и финальном слайде.** Хелпер `logoCorner()`
для внутренних слайдов не вызывается.

## 7. Готовые компоненты

Все из реальной колоды 2B Групп, `_deckbuild/build_2b.js`.

### Роадмап процесса (слайд 2)

Кружок с номером на соединительной линии, заголовок этапа, описание, ниже — карточка
«Возможные боли» списком.

```js
function roadmapStep(n, title, desc, pains) { /* колонка: circle → title → desc → pains */ }
function roadmap(steps) {
  return `
    <div style="position:relative; padding-top:6px">
      <div style="position:absolute; top:28px; left:70px; right:70px;
                  height:2px; background:${CARD_BORDER}"></div>
      <div style="display:flex; gap:14px; position:relative; align-items:stretch">
        ${steps.map((s) => roadmapStep(...s)).join('')}
      </div>
    </div>`;
}
```

Линия — абсолютно позиционированный `div` на уровне центра кружков (`top` = половина
диаметра + `padding-top`), с отступами по краям, чтобы не торчала за крайние кружки.

### Блок цены (слайд 4)

Слева тёмная плашка с ценой, справа состав двумя смысловыми группами с подписями.

```js
function planRow(name, sub, price, groups) {
  // groups: [['Что делает', [...]], ['Что получаете', [...]]]
  // слева: width:340px, linear-gradient(135deg, DARK_BG_FROM, DARK_BG_TO)
  //        name 26px/800 · sub 13.5px · price 44px/800 · «в месяц» 14px
  // справа: flex:1, две колонки flex:1 с uppercase-подписью акцентным цветом
}
```

Группы **не смешивать**: в одной колонке пункты одного рода. Проверяй, что «что получаете»
не состоит из трёх пунктов про одно и то же.

### Карточки возможностей (слайд 3)

Обычные `.card` в сетке `.cards-3`, внутри — заголовок и `ul` буллетов. Один продукт —
три карточки по группам возможностей, каждая отвечает на боли слайда 2.

## 9. Порядок работы

```bash
node _deckbuild/prep_<клиент>.js     # один раз: ассеты → img.json
node _deckbuild/build_<клиент>.js    # правки текста и вёрстки — здесь
node _deckbuild/render_<клиент>.js   # скриншоты + отчёт + PDF
```

После рендера:

1. Прочитать отчёт о переполнении — все слайды `ok`
2. Посмотреть скриншоты изменённых слайдов **глазами**
3. Отдать PDF ссылкой, назвать открытые вопросы списком

Артефакты сборки (`deck/`, `shots/`, `overflow-report.json`) остаются в папке проекта —
клиенту уходит только PDF.
