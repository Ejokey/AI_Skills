# Пайплайн HTML → PDF

## Стек

```
_deckbuild/build_<тендер>.js   (генератор HTML-слайдов, template literals)
   ↓
deck/deck.html
   ↓
Playwright headless Chromium  (1280×720 px, printBackground: true)
   ↓
_deckbuild/render_<тендер>.js  (page.pdf(), PNG по слайдам, overflow-report.json)
   ↓
tenders/<Тендер>/03-proposal/КП_<...>.pdf
```

Целевой размер слайда — **1280×720 px**. Это же соотношение используется при пересчёте в PPTX (`S = 13.333/1280`, см. `pptx-export.md`).

`printBackground: true` в `page.pdf()` обязателен — без него Chromium выбрасывает все фоновые заливки и градиенты, и слайды выходят белыми.

Скрипты `build_*.js`/`render_*.js` держатся в **`_deckbuild/` в корне репозитория**, не в папке тендера — Bash-инструмент искажает кодировку при проверке прав на путях с кириллицей, поэтому команда вызова остаётся латиницей (`node _deckbuild/build_alean.js`). Сам Node внутри пишет в кириллические пути (`DST`, `img.json`, итоговый PDF) без проблем — специальной ASCII-копии, в отличие от Python-скриптов, не нужно.

CSS переиспользуется между колодами через `_deckbuild/css.txt` — это **тело JS template-литерала**, а не сырой CSS. Подключается через `new Function('ACCENT', ..., 'return \`' + cssTemplate + '\`;')(...)` с передачей цветовых констант. Прочитать файл и вставить его как обычный текст — сломает вёрстку: в разметку попадут неподставленные `${...}`.

## Ассеты и img.json

Все изображения кодируются в base64 и складываются в `img.json` через `make-img-json.js`. Это делает HTML самодостаточным — Playwright не ходит за файлами по относительным путям.

**Важно:** после добавления новых картинок нужно **перезапустить `make-img-json.js`**. Забытый перезапуск даёт пустые места на слайдах при том, что файл картинки на диске существует — типичный источник путаницы при отладке.

## Проверка переполнения

Меряй **относительно верхнего края футера**, а не низа слайда.

Слайд высотой 720px с футером, занимающим нижние ~60px, даёт реальную рабочую область до ~660px. Проверка «текст не выходит за 720» пропускает случаи, когда абзац наезжает на футер — визуально это выглядит как грязь, и такие вещи пользователь ловит на скриншотах.

`render_*.js` делает это программно через `page.evaluate()`: для каждого `.slide` берёт `getBoundingClientRect()` футера и сравнивает с максимальным `bottom` среди прочих элементов слайда, плюс отдельно проверяет `scrollHeight > clientHeight` у `.body` (контент обрезан flex-контейнером, даже если внешне не долез до футера). Результат — `overflow-report.json`. Прогоняй по всем слайдам, не проверяй на глаз только несколько.

**После любого подъёма кегля или уплотнения вёрстки — переполнение перепроверяется заново.** Крупный шрифт первым делом ломает слайды с длинными списками или таблицами на 5+ строк.

## Изображения в вёрстке

**Сплющенные логотипы.** Причина — рассинхрон DPI между метаданными файла и фактическим размером. Лечится в два шага:
1. обрезать пустые поля вокруг логотипа
2. задать `height: Xpx; width: auto` — принудительно зафиксировать пропорцию

Не пытайся чинить это подбором `width`/`height` вручную — при следующей замене картинки всё повторится.

**Высокие скриншоты.** При cover-обрезке используй `object-position: top`. По умолчанию обрезка идёт от центра, и у скриншотов сайтов срезается шапка — то есть ровно то, что делает скриншот узнаваемым.

**Скриншот должен соответствовать подписи.** Проверяй визуально (Read по PNG из `deck/shots/`), а не только по имени файла — расхождение между тем, что подпись слайда обещает («новостной раздел с умным поиском»), и тем, что реально на скриншоте (например, виджет ИИ-чата), не ловится программной проверкой переполнения.

## Синхронизация при изменении количества слайдов

Три места, которые должны совпадать. Пропуск любого даёт битую колоду:

1. **`footer(n)`** — иначе в подвале «слайд 12 из 14» при 15 слайдах; заодно проверь константу `TOTAL` в начале обоих скриптов (`build_*.js` и `render_*.js`)
2. **номера целевых страниц в TOC** — иначе кликабельное оглавление (в PPTX-версии) или просто текст оглавления ведёт не туда
3. **диапазон в `render_*.js`** (`pageRanges` у `page.pdf()`) — иначе последние слайды просто не попадут в PDF

Проверяй все три вместе, одним проходом, при вставке или удалении слайда из середины колоды.

## Шрифты

Playwright рендерит системные шрифты хоста, доступные Chromium — на Windows это обычно шрифты из `C:\Windows\Fonts\`. Кириллица в HTML-вёрстке (в отличие от прямой правки готового PDF через PyMuPDF, см. `pdf-editing.md`) рендерится штатно, специальных TTF подключать не требуется — Chromium сам подбирает системный шрифт с нужными глифами. Для брендовых гарнитур (например, Manrope для Интер РАО) шрифт подключается как обычно — через `@font-face` или Google Fonts, если сборка идёт с доступом в сеть.

## QA-инструменты

- Скриншоты по слайдам из `render_*.js` (`deck/shots/slide-NN.png`) — основной способ визуальной проверки, читай через инструмент Read
- `overflow-report.json` — программная проверка переполнения, смотри перед любой отдачей файла
